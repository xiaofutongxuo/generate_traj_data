Trajectory GUI 使用手册

适用项目：/home/ubuntu/Public/hzq/generate_traj_data

文档用途：帮助使用增强版 GUI 浏览、筛选、删除、补充、编辑和保存 VLA/手工/cluster 生成的伪 GT 轨迹。

真实 GT 只来自原始数据集 output 只保存伪 GT 默认逐视频帧浏览 保存前会做动力学优化

1. 手册定位

增强版 GUI 的核心任务是：在每个视频帧 t0_us 上查看模型生成的多样化轨迹， 对不合理轨迹进行删除、速度优化、几何编辑，必要时补充 manual Bezier 或 cluster center 轨迹， 最后把清洗后的伪 GT 写回 output parquet。

一句话理解数据语义： /home/ubuntu/Public/train_data 里的实车轨迹是真实 GT； output/{dataset}/{clip}.egomotion.parquet 里的行都是伪 GT，包括 vla、manual_bezier、cluster_center 等。

2. 启动 GUI

推荐启动命令

cd /home/ubuntu/Public/hzq/generate_traj_data

/home/ubuntu/Public/lxh/alpamayo_1.5/ar1_venv/bin/python trajectory_gui_enhanced.py \
  --data_root /home/ubuntu/Public/train_data \
  --output_dir /home/ubuntu/Public/yzb/generate_traj_data/output \
  --calibration_dir /home/ubuntu/Public/yzb/triplane_tokenization/cailibration \
  --no_restore_last

常用启动参数

参数 含义 常用值
--data_root 原始数据集路径，GUI 从这里读取图像、history 和真实 GT。 /home/ubuntu/Public/train_data
--output_dir VLA/manual/cluster 伪 GT parquet 输出目录。 /home/ubuntu/Public/yzb/generate_traj_data/output
--calibration_dir 旧集中式 JSONL 标定兜底目录；GUI 会优先读取 --data_root 中每个数据集自己的 XML 标定。 /home/ubuntu/Public/yzb/triplane_tokenization/cailibration
--index_mode 样本索引来源。默认逐视频帧浏览。 video_frames / generated / merged
--frame_stride 逐视频帧模式下的帧间隔。 1
--start_dataset、--start_clip、--start_t0 启动后直接跳到指定 dataset/clip/t0。 需要复查某一帧时使用
相机标定推荐放在 /home/ubuntu/Public/train_data/{dataset}_converted/calibration/。 如果只有 Vision_calibration.tar.gz，需要先解压到对应数据集目录。 GUI 会把 fc120 映射为 FC， fc30 映射为 FC_FAR， rl/rr/fl/fr/rc 映射为对应的大写相机名。
远程显示注意： 如果 $DISPLAY 为空，代码会尝试使用 DISPLAY=:1。 这通常意味着窗口会出现在服务器桌面或 VNC 中，而不是 VS Code Remote SSH 的终端里。

3. 界面区域

区域 作用 重点看什么
顶部工具栏 选择 Dataset、Clip、t0，并 Jump 到指定样本。 确认当前帧是不是自己要检查的 t0_us。
左侧 BEV 俯视图显示 history、GT future、伪 GT、manual 预览、cluster 预览和停车点。 轨迹形状、终点、是否突然跳变、是否偏离道路趋势。
左下速度面板 Diversity Speed Profile 与 GT Speed Profile。 历史速度、未来速度、当前帧 F0、速度是否平滑。
中间相机图像 显示 RL/FC/RR 等相机画面，并投影轨迹。 轨迹投影是否符合画面道路、障碍物和行驶趋势。
右侧 Trajectories 列出当前 t0 下 output 中的伪 GT 轨迹。 选择轨迹、查看来源、识别建议删除行。
右侧 CoT/Cluster 区域 显示模型 CoT 文本，并选择 cluster center 类型和编号。 辅助理解模型意图，或快速追加某类轨迹。
底部按钮区 保存、删除、编辑、Bezier、cluster、GT 修复等操作入口。 操作前确认当前是否有未保存状态。

4. 浏览样本

逐帧浏览

默认 --index_mode video_frames --frame_stride 1 会按主视频时间戳逐帧浏览。 即使当前帧还没有生成轨迹，GUI 也会显示图像、history 和真实 GT，右侧轨迹列表可能为空。 逐帧索引会要求当前帧和后续 6.4s 真实 egomotion 连续可用；相邻 egomotion 缺口不超过 0.3s 时会插值补小漏帧， 超过 0.3s 或最后一个 clip 尾部没有足够 future 时会过滤该帧，避免显示外推出来的 GT。 如果当前 clip 结尾能和下一个 clip 按 timestamp 连续接上，GUI 会自动使用下一个 clip 的 egomotion。

用顶部 Dataset / Clip / t0 下拉框选择样本，或用左右方向键逐帧切换。
看状态栏中的覆盖率，例如 Video t0: N | Generated t0: M | Missing: K。
如果状态栏显示 Current: no generated，表示当前视频帧还没有 output 伪 GT 行。

只看已生成轨迹

如果只想浏览 output parquet 中已经有生成结果的帧，可以启动时使用： 

--index_mode generated

5. 轨迹列表与颜色

右侧 Trajectories 列表只显示 output 中的伪 GT 行。真实 GT 不在这个列表里， 而是从原始数据集中读取并单独显示。

标记或颜色 含义
[√] 当前轨迹通过速度平滑性初筛。
[×] 当前轨迹速度不够平滑，建议重点检查或删除。
红色轨迹线 速度诊断认为不平滑的伪 GT。
绿色历史速度线 真实历史轨迹速度，不是伪 GT。
黄色 GT 轨迹 从原始数据集读取的真实 GT future。
青色 manual 预览 当前正在绘制的手工 Bezier 预览。
橙色 cluster 预览 当前选择的 cluster center 预览。

6. 速度曲线

速度面板怎么看

  • Diversity Speed Profile：绿色 history + 当前选中伪 GT 的未来速度。
  • GT Speed Profile：绿色 history + 真实 GT future 速度；GT 速度由原始 GT 位置差分得到后会做轻量显示平滑。
  • History 会在显示层做轻量去噪，固定第一帧和当前帧不动；绿色 history 速度线、BEV history 和 hover 高亮使用平滑后的点，不修改原始数据。
  • 横轴约为 F-15..F63，其中 F0 是当前帧。
  • 竖向虚线表示当前帧 F0。
  • 录制开头真实历史帧不足时，不会强行显示不存在的历史速度。

优化伪 GT 速度

在右侧轨迹列表中选中一条非 GT 伪 GT。
点击 优化速度曲线。
GUI 会平滑速度、沿原路径重采样，并执行加速度限制。
如果效果合适，点击速度面板下方的接受按钮；不合适就取消。
接受后会写回当前 output parquet 对应行。
保存伪 GT 时还会调用 traj_gui_enhanced.dynamics 做保守动力学优化，并重算 vx/vy/vz/qx/qy/qz/qw/curvature。

7. 删除扩充轨迹

删除功能采用“两阶段”策略，避免误删：第一次删除只是在 GUI 中隐藏；只有确认保存后才真正从 parquet 删除。

在右侧列表中选中要删除的非 GT 轨迹。
按 Delete / Backspace，或点击 Delete (Del)。
轨迹会从列表、BEV 和相机投影中消失，但 parquet 暂时不变。
如果误删，点击 Undo Delete 恢复最近一次删除。
确认无误后点击 Confirm Save (Ctrl+S)，这时才真正写回 parquet。
切换样本前如果还有 pending delete，GUI 会提示先保存或撤销。真实 GT 受保护，不能作为 output 轨迹删除。

8. 编辑已保存伪 GT

该功能用于直接修改已经保存到 output 的非 GT 轨迹几何形状，例如 VLA 生成轨迹、 manual Bezier 轨迹或 cluster center 轨迹。

操作流程

在右侧列表中选中一条非 GT 轨迹。
点击 Edit Traj。
BEV 上会出现若干白色关键帧手柄，默认每 8 帧一个，并包含最后 endpoint。
用鼠标左键拖动某个手柄。GUI 会对附近帧做局部形变，并立即执行 dynamics 优化。
满意后点击 Save Edit 写回原 parquet 行。
不满意可点击 Cancel Edit 放弃修改，或点击 Restore Edit 回到进入编辑时的轨迹。

适合修改什么

  • 终点稍微偏左或偏右。
  • 中间轨迹形状不顺，需要轻微调整弯曲趋势。
  • VLA 轨迹整体合理，但局部点位和图像投影不一致。
这是第一版几何编辑。真实 GUI 使用时仍建议重点检查手柄密度、拖拽影响范围和优化后轨迹是否符合预期。 如果拖动过大，优化器会尽量收敛到更合理的轨迹，但仍需要人工复查。

9. 手工 Bezier

手工 Bezier 用于在当前帧上新增一条人工扩充轨迹。它不是修改已有轨迹，而是追加一条新的 source=manual_bezier 行。

勾选 Draw Bezier。
在 BEV 或 FC 图像中点击添加控制点。
右键拖拽控制点可以调整曲线；BEV 和 FC 的控制点会尽量同步。
如需要最终停车，点击 Add Final Stop，并通过 Stop Time(s) 设置停车时长。
点击 Save Curve Traj，把手工轨迹追加到当前 parquet。

手工控制点和停车点会保存到 output/manual_points.json，用于后续恢复和维护。

10. Cluster center

Cluster center 用于快速从已有轨迹簇中心中挑选一条合适的扩充轨迹。类别包括 stop、straight、left、right、s_curve。

在右侧 Cluster 区域选择类别和具体 center。
BEV 和相机图像中会显示 cluster 预览。
可以拖拽 cluster endpoint 进行微调，候选会经过加速度、曲率和位移限制。
点击 Confirm Save，将当前 cluster 预览追加为 source=cluster_center。

Save Bezier Center 会把当前手工 Bezier 保存为新的 cluster center； Delete Current Bezier Center 只删除由 Save Bezier Center 创建的 center， 不会删除已经写入 output parquet 的轨迹行。

11. GT 显示与诊断

真实 GT 只从 /home/ubuntu/Public/train_data 读取，用于显示、对比和诊断。 GUI 不再把真实 GT 写入 output parquet。

  • GT Speed Profile 显示 history + GT future 速度。
  • Repair GT 用于查看基于速度/加速度限制修复后的 GT future。
  • Restore GT 切回原始 GT future 显示。
  • 状态栏会显示 GT 加速度范围、最大步长和异常数量。
output 中历史遗留的 source=gt 行会被视为旧数据污染。GUI 不会把这些行放入伪 GT 列表， 也不会把它们当作真实源数据 GT。

12. 保存规则

操作 保存时机 写到哪里
删除轨迹 点击 Confirm Save (Ctrl+S) 后真正删除。 当前 active parquet 原文件。
速度优化 接受优化结果后写回。 当前轨迹对应 parquet 行。
已保存轨迹几何编辑 点击 Save Edit 后写回。 当前轨迹对应 parquet 行。
Save Curve Traj 点击按钮后追加新行。 当前 clip parquet，source=manual_bezier。
cluster Confirm Save 点击按钮后追加新行。 当前 clip parquet，source=cluster_center。
manual 控制点 保存/删除相关操作后同步。 output/manual_points.json。
当前 GUI 的真实行为是直接写回 active parquet，不是写入 filtered/ 子目录。 做大批量清洗前，建议先备份 output。

13. 快捷键

快捷键 功能
← / → 切换上一个/下一个样本。
↑ / ↓ 切换当前样本中的上一条/下一条伪 GT 轨迹。
Delete / Backspace 将当前轨迹加入 pending delete。
Ctrl+S 确认保存 pending delete 等全局保存操作。若有正在进行的几何编辑，会先提示处理编辑状态。
Tab 切换当前投影相机。
+ / - 切换 cluster center。
Q 退出 GUI。

14. 常见问题

窗口没有出现在本地屏幕

检查 $DISPLAY。如果为空，GUI 可能打开到了服务器的 :1 桌面或 VNC。 远程使用时需要 VNC、桌面会话或 SSH X11 forwarding。

当前帧没有轨迹

如果状态栏显示 Current: no generated，说明这个视频帧还没有 output 伪 GT。 这不是 GUI 漏帧，而是该帧尚未生成轨迹。可以运行逐帧推理补齐。

右侧列表中看不到 GT

这是正常行为。真实 GT 从原始数据集读取并单独显示，不再作为 output 轨迹行参与删除或编辑。

删除后想恢复

如果还没有点击 Confirm Save，可以用 Undo Delete 恢复。 如果已经保存写回 parquet，则需要从备份恢复。

几何编辑时不能切换轨迹或样本

GUI 会保护正在编辑的轨迹。请先点击 Save Edit 或 Cancel Edit。

历史速度没有显示

录制刚开始时可能没有足够真实历史帧。GUI 不会绘制不存在的历史数据，这是预期行为。

15. 推荐清洗流程

启动 GUI，确认 Dataset、Clip、t0 和状态栏覆盖率。
先看 BEV 总体形状，再看 FC/RL/RR 投影是否符合道路和画面。
查看速度面板，重点关注速度尖刺、突然停车、历史到未来速度是否突变。
对明显错误轨迹使用 Delete/Backspace staged 删除。
对形状基本正确但速度不平滑的轨迹，使用 优化速度曲线。
对形状需要微调的已保存轨迹，使用 Edit Traj 拖动 BEV 手柄并 Save Edit。
如果缺少合理候选，使用 manual Bezier 或 cluster center 追加新伪 GT。
确认删除和新增/编辑结果无误后，保存并切到下一帧。
建议验收标准： 每个保留下来的伪 GT 轨迹在 BEV 和相机投影中都合理，速度曲线没有明显尖刺， 轨迹不会出现突跳、反向、过大曲率或明显不符合车辆动力学的局部形变。
